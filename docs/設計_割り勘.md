# 割り勘・立て替え（3.1）

2026-10-16 のご要望から。費用ごとに「誰が払ったか」「誰と割り勘するか」を持ち、最後に「さくら → 自分 ¥3,200」のような受け渡しを出す。**無料**（Pro ではない）。

## 決めたこと（2026-10-18）

- 精算に使う金額は **実際に使った金額を優先**し、無ければ予定の金額。
- 割り方は **選んだ人で同じ額ずつ**が基本。2026-10-19 に **人ごとに金額を決める割り方**も足した（決めた人はその額、空欄の人は残りを同じ額ずつ）。
- アプリを使っていない同行者・予定にしない支出・済ませた精算は、**旅行に新しい欄（`splitJSON`）を足して**持つ（CloudKit の Production 反映が要る）。

## データ

| どこ | 項目 | 中身 |
|---|---|---|
| 予定（`ScheduleItem`、`daySchedulesData` の JSON） | `paidBy` / `splitWith` / `splitAmounts` | 払った人・割り勘する人（nil は全員）・人ごとに決めた金額（nil は均等） |
| 予約（`Reservation`、`reservationsData` の JSON） | `paidBy` / `splitWith` / `splitAmounts` | 行程に出ていない予約だけで使う |
| 旅行（Core Data `TravelPlanEntity.splitJSON`、共有レコード `SharedTravelPlan.splitJSON`） | `TripSplit` | 同行者（`TripCompanion`）・支出と精算（`TripExpense`） |

- 割り勘に入る人：共有していれば `sharedWith`、していなければ自分。どちらにも同行者（id は `companion-<UUID>`）を足す。
- **払った人が無い費用**：共有していない旅行では自分が払ったことにする（今までの費用をそのまま割り勘にできる）。共有している旅行では「払った人が未定」として精算に入れず、明細の金額の下に「払った人が未定」と出す。共有した旅行で新しく金額を入れた予定は、入れた人が払ったことにする。
- **済ませた精算**は、`isSettlement` の付いた支出として持つ（払った人 → 受け取った人1人）。費用の合計には入れず、受け渡しの計算でだけ差し引く。「取り消す」で済んでいないことに戻す。
- 支出の日が旅行の外なら「旅行の前後」にまとめる。
- 同行者を外すと、その人が払った費用は「払った人が未定」に、その人が負担していた分は残りの人で分ける。

## 計算（`TripSplitLedger`）

1. 人ごとに、払った額と、負担する額を足す。負担する額は `TripSplitLedger.shares`：金額を決めた人はその額、決めていない人は残りを同じ額ずつ。全員決めて合計が合わなければ、差を全員で同じ額ずつ足し引きする（画面では、合わないと保存できない）。
2. 済ませた精算を足し引きして、受け取る額（マイナスは払う額）を出す。
3. 払う額の大きい人から、受け取る額の大きい人へ順に渡す（受け渡しの回数がなるべく少なくなる）。円未満は四捨五入し、1円に満たない差は出さない。

外の世界に触らないので、`GoTravelTests/TripSplitTests.swift` で確かめている。

## 共有のマージ

`SharedPlanMerge.combine` で、同行者と支出を1つずつ（id で）突き合わせる。予定・メモと同じ3つ（手元・相手・前回）の判断。

## 旧バージョンとの関係

- 3.0 以前は `paidBy` / `splitWith` を知らないので、**3.0 以前の端末が予定を直すと消える**（全員・払った人未定に戻る）。`participantIds` と同じ性質。
- 3.0 以前は `splitJSON` を読まないので、同行者・支出は出ない（消えはしない）。

## CloudKit の Production 反映（3.1 のリリース前に必ず）

| どこ | 項目 |
|---|---|
| Core Data（プライベートDB） | `CD_TravelPlanEntity.CD_splitJSON`（String） |
| パブリックDB | `SharedTravelPlan.splitJSON`（String） |

1. `CoreDataManager.swift` の `initializesCloudKitSchemaOnLaunch` を一時的に true にし、サインインした端末でデバッグ実行する（`CD_splitJSON` が Development にできる）。戻すのを忘れない。
2. 共有した旅行で同行者を足すか支出を入れる（`SharedTravelPlan.splitJSON` が Development にできる）。
3. CloudKit Console で Development に2つあることを確かめ、Deploy Schema Changes で Production へ。
4. `docs/共有機能.md` の「まだ反映していない」を、反映した日付に直す。

## 画面（費用のタブ、`BudgetSummaryView`）

家計簿のような1枚の紙にした。色のグラデーション・影・見出しごとのアイコンをやめ、細い線と余白で区切る。

1. 合計（使った金額 / 予算、細い線1本で予算との差）
2. 精算（受け渡しと「済み」、済んだもの、ひとりずつ、割り勘に入る人の札と「＋ 一緒に行く人」）。1人のときは同行者を足す案内だけ
3. 日ごとの明細（金額の下に「自分払い・父をのぞく」を小さく添える）。押すと払った人・割り勘する人を選べる。支出は中身も直せる
4. 為替レート（外貨を使ったときだけ）
5. 「＋ 支出を足す」

精算の見出しの「送る」で、受け渡し・済んだもの・ひとりずつの払った額と負担する額を文字にして、LINE などで送れる。

前の「割る人数」（`customSplitCount`）の画面はやめた。値は旅のしおりの「1人あたり」でだけ使っている。
