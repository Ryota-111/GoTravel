# 設計：「移動」の予定と「時間未定」の予定（3.4）

## きっかけ（ご意見）

- 2026-11-05（3.3）「バス乗る時間とか、どのバスに乗るかとか予定表に入れれるようにしたい」
- 2026-11-06（3.3）
  - 「時間が決まっていない『時間未定』を作って欲しい。時間は決めてないけど、予定は入れておきたい。他の予定の前後どこにでも動かせるように」
  - 「移動や宿泊などの項目（カテゴリ）を作って、移動の時は駅の名前が入れられる（発着点）と嬉しい。今は場所が1か所しか入れられない」

## 今あるもの（作り直さない）

- 予約（`Reservation`）：飛行機・新幹線は出発地・到着地・便名・座席を持てる。「行程にも追加する」で出発と到着の2件の予定になる
- 予定と予定の間の移動手段（`transportToNext`、3.2）：手段の印と線だけ。駅やバスの名前は入れられない
- 予定の終わりの時刻（`endTime`）と、着いた先の時計（`endTimeZoneIdentifier`）：1件で「15:00 パリ → 23:00 ドーハ」を表せる

足りないのは「予定を足す画面から、乗り物・発着地・便や系統を1件で入れる」入口と、その見せ方。

## A. 「移動」の予定

### データ（`ScheduleItem.move`、`Models/ScheduleMove.swift`）

```swift
struct ScheduleMove {
    var mode: String        // TransportMode の rawValue（train / bus / plane / ship / car / taxi / walk）
    var line: String?       // 便名・系統・列車名（「阪急バス 12系統」「のぞみ21号」）
    var platform: String?   // のりば・番線（「3番のりば」「14番線」）
    var seat: String?       // 座席（「7号車 3D」）
    var from: MovePlace?    // 出発地（名前・住所・位置）
    var to: MovePlace?      // 到着地
}
```

- 予定の JSON の中の項目なので、CloudKit のスキーマ変更は要らない
- **予定の `location`・位置・住所には出発地を入れる。** 地図のピン・「案内」・古い版の表示がそのまま効く
- **名前を入れなければ「梅田 → 京都」を名前にする。** 古い版（3.3 まで）は `move` を読まないが、名前で中身が分かる
- 時刻は今までどおり：始まり＝出発、終わり（`endTime`）＝到着。時差をまたぐ移動も今の仕組みのまま
- 古い版で予定を直すと `move` は消える（名前・出発地・時刻は残る）。共有した旅行の参加する人と同じ扱い

### 画面

- 予定を足す・直す画面の一番上で「予定 / 移動」を選ぶ
- 「移動」では：手段（電車・バス・飛行機・船・車・タクシー・徒歩）、出発地 → 到着地（名前を打つか、地図で探す。入れ替えボタン付き）、出発・到着の時刻、便名・系統、のりば・番線、座席
- 日程の行：名前の下に「🚌 阪急バス 12系統 · 3番のりば」。名前を自分で付けたときは、その下に「梅田 → 京都」も出す
- 場所の行は「出発地 → 到着地」にし、「案内」は出発地へ（出発前に乗り場へ向かうため。出発地の位置が無ければ到着地）

### 予約の種類に「バス」「船・フェリー」を足す

高速バスやフェリーにも予約番号がある。飛行機・新幹線と同じく、出発地・到着地・便名・座席を入れられるようにする。

- **保存では「電車（train）」として書き、`kindDetail` に "bus" / "ferry" と添える**（駐車場と同じやり方）
- 古い版は知らない種類を「その他」として読み、出発地・到着地が出なくなる。「電車」なら発着地まで出る

### 予約との連携

- **予約 → 行程**：乗り物の予約（飛行機・電車・バス・船）は、**今までどおり「〇〇 出発」「〇〇 到着」の2件**。
  それぞれの時刻・場所で並び、地図には出発地と到着地のピンが立つ。
  **出発にだけ `move`（乗り物・便・のりば・座席）を持たせ**、行程に「✈︎ NH991 · 第2 · 座席 12A」と添える（`ScheduleItem.isRouteLeg`）。到着は時刻と場所だけ
  - 一度は移動の1件にまとめたが、到着の時刻が自分の行・ピン・ロック画面の「次の予定」として出なくなるため、2件に戻した（2026-11-07）
  - 3.3 までに入った添え書きの無い2件は、予約か行程で直したときに添え書きが付く
  - 出発・到着の予定を直す画面は、今までどおり場所1か所の予定として直す（乗り物・便は予約の画面で）
- **行程の移動に予約番号を入れる**（足す・直す画面）：予約として残す（`makeReservation(fromMoveItemID:)`）。
  移動の1件がそのまま出発の予定になり（id・参加する人などが残る）、到着の予定が足される。つないだあとは行程から予約番号も直せる（`setConfirmationNumber`）
- **予約の画面の「予定から持ってくる」**：移動の予定なら乗り物・到着地・到着の時刻・便・のりば・座席まで引き継ぐ。保存すると、新しく作らずに選んだ予定をつなぐ（`link(scheduleItemID:to:)`。宿などの予定でも同じ）
- 予約の電車・バス・船でも「のりば・番線」（`terminal`）を持てる（前は飛行機のターミナルだけで、保存のときに消えていた）
- 行程で足した移動の1件は、地図に出発地と到着地の両方のピンを立てる

## B. 「時間未定」の予定

### データ

- `ScheduleItem.isTimeUndecided: Bool?`（true のときだけ未定）
- **`time` は「並ぶ位置」として使い続ける。** 時刻を必ず持つ前提の所（並び順・共有の合わせ込み・時間帯の付け替え）がそのまま動く
- 未定の予定の `time` は、**すぐ前の予定と同じ分の、1〜59秒目**にする（前の予定が無ければ次の予定の1分前）
  - 並べる比較（`ScheduleItem.chronologically`）は分まで同じなら、時刻のある予定を先にし、未定どうしは秒で並べる
  - 古い版では、前の予定と同じ時刻の予定として、そのすぐ後ろに出る（大きくずれない）
- 終わりの時刻・前日/翌日のずれは持たない

### 画面

- 予定を足す・直す画面の時間の欄に「時間未定」のスイッチ。オンにすると時刻の入力を隠し、「どこに入れるか」（いちばん前／〇〇のあと）を選ぶ。はじめは一番うしろ
- 日程の時刻の列は「未定」。並べ替え（`ScheduleReorderView`）で前後どこにでも動かせる。動かしたら、新しい前の予定に合わせて位置を付け直す
- 直す画面でスイッチを切ると、前の予定の時刻から入れ始める

### 時刻を使う所での扱い

| 所 | 扱い |
| --- | --- |
| 日程の「次の予定」の光 | 未定は飛ばす |
| ウィジェット・ライブアクティビティ | 出さない（時刻が無いと「今・次」が決まらない） |
| iPhone のカレンダーへの書き出し | その日の終日の予定として入れる |
| 予定と予定の間の空き時間 | 未定が絡む区間は出さない |
| しおり・共有カード・PDF・並べ替え | 時刻の代わりに「未定」 |
