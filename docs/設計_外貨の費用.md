# 設計：外貨の費用（無料）

海外旅行で「ドルで払った」「ウォンで払った」金額をそのまま入れ、円に直して予算に入れる。
2026年10月。時差のご要望が続いたことから、海外旅行で使っている人が一定数いると判断した。

## 決めたこと

- **無料の機能にする**（Pro にしない）
- **レートは旅行ごとに自分で入れる**（両替したときのレート）。自動で取ってこない
  - 通信が要らない。外部サービスに頼らない
  - 実際に両替したレートに合わせられる
- 同じ旅行の同じ通貨は、**いつも同じレート**にそろえる（旅行ごとのレート）

## データの持ち方

- 円の金額（`ScheduleItem.cost` / `actualCost`、`Reservation.cost`）は今までどおり持つ。
  予算・割り勘・書き出しなど、円で計算している所は何も変えない
- 外貨で入れたときだけ、その元を `foreignCost`（`ForeignCost`：通貨・レート・外貨の予算・外貨の実績）として横に持つ。
  円の金額 = 外貨 × レート（四捨五入）
- **レートは旅行そのものではなく、費用を入れた予定・予約の中に持つ。**
  旅行に項目を足すと Core Data と共有レコード（パブリックDB）の両方でスキーマの変更と Production への反映が要るため。
  予定・予約は JSON（`daySchedulesData` / `reservationsData`）の中なので、項目を増やしてもスキーマは変わらない
- 旅行のレートは「その旅行でその通貨を使っている費用のレート」（`TravelPlan.exchangeRates`）。
  レートを入れた・直したときは `TravelPlan.setExchangeRate` で同じ通貨の費用をすべて直し直す

## 画面

- 予定の追加・編集、予約の編集の費用欄に、通貨の選択を付けた（`CurrencyCostFields`）
  - 外貨を選ぶと「1 USD = ○ 円」の欄が出る。この旅行で前に入れたレートが最初から入る
  - この旅行で外貨を1種類だけ使っていれば、予定の追加は最初からその通貨にする
- 予算の画面に「為替レート」のカードを出す（外貨を使っているときだけ）。ここで直すと全部に効く
- 予算の明細には、外貨の元の金額（"$120"）と、レートが無いものには「レート未入力」を出す

## 気をつけること

- レートが未入力のあいだ、その費用は円の金額が空なので**予算の合計に入らない**。予算の画面で「レート未入力」と出して入れてもらう
- 古いバージョン（`foreignCost` を知らない版）が共有した旅行を保存すると、外貨の元は消えて円の金額だけ残る（壊れはしない）
- 予約確認メールの金額は円だけ読む（外貨は読まない）
