# 設計：共有した旅行計画をウェブで見る（3.5）

## きっかけ

「Android の友達と共有できない」（2026-08〜10 に5件）、「ウェブからも編集したい」（2026-11-03）。
Android 版やウェブでの編集は大きすぎるので、まず**見るだけのページ**を作る。

## 仕組み

```
アプリ（共有画面）                      公式サイト（Cloudflare Pages）
「ウェブでも見られるようにする」 ──→  SharedTravelPlan.webViewEnabled = 1
                                       SharedTravelPlan.webViewToken = 見る用の合言葉（オンにするたびに作り直す）
                                        ↑
ブラウザ ── /v/<計画のID>/<合言葉> ──→ Pages Functions（functions/v/[planId]/[token]/）
                                        └─ CloudKit Web Services（server-to-server key）で
                                           レコード名 shared_<計画のID> の1件を読み、
                                           オンで合言葉が同じときだけ HTML を組み立てて返す
```

- **リンクにもページにも共有コードを出さない**（ultrareview の指摘、3.5 を出す前に直した）。
  共有コードは「共有に参加」の合言葉で、参加すると直せる。見るだけのつもりで送ったリンクから、直せる人が増えてはいけない。
  見る用の合言葉はオンにするたびに作り直し、オフにすると消す。オフにすれば、前に送ったリンクはもう開けない
- **共有をやめるときは、先にウェブを止めて、止まったのを確かめてから**共有をやめる。
  共有レコードの削除は待たずに進むので、削除に失敗するとウェブで見え続けてしまうため。止められなければ共有もやめない
- 前の形の `/s/<共有コード>` は、いつも「見られません」を返す

- **見られるのは、共有画面でオンにした旅行だけ**（計画を作った人が変えられる）。オフ・共有をやめた・コード違いは、どれも同じ「見られません」
- 出すもの：アプリで見られるもの全部（日程・移動・時間未定・予約と予約番号・行きたい場所・やりたいこと・みんなの持ち物・メモ・費用）。
  パブリックDBに載っていないもの（各自の持ち物・お土産・自分だけのメモ）は、もともと出ない
- 検索には出さない（`noindex`・`X-Robots-Tag`）。キャッシュは見る人の端末に60秒だけ（オフにしたら、すぐ見られなくなる）
- 地図のリンクは Google マップ（iPhone でも Android でも開ける）
- 表紙の写真は `/v/<計画のID>/<合言葉>/cover`。CloudKit の写真の URL は時間で切れるので、毎回取り直して渡す（LINE などの OGP にも使う）
- 鍵はサーバー（Cloudflare の環境変数）にだけ置く。ブラウザには渡さない

コード：アプリは `Models/SharedWebPage.swift`・`CloudKitService.setSharedWebPageEnabled`・`ShareTravelPlanView.webPageSection`。
サイトは `travory-web` の `functions/_lib/`（`cloudkit.ts` 署名と読み込み、`shared-plan.ts` 読み直し、`render.ts` ページ、`handler.ts`）。

## 出す前にやること（1回だけ）

### 1. ウェブ用の鍵を作る（CloudKit Console）

ターミナルで鍵を作る（**秘密鍵はリポジトリに入れない**）。

```bash
openssl ecparam -name prime256v1 -genkey -noout -out ~/travory-web-cloudkit.pem
openssl ec -in ~/travory-web-cloudkit.pem -pubout
```

1. [CloudKit Console](https://icloud.developer.apple.com/) → コンテナ `iCloud.com.gmail.taismryotasis.Travory`
2. **Tokens & Keys**（「トークンとキー」）→ **Server-to-Server Keys** の ＋
3. 名前を「travory-web（見るページ）」にし、上で出た公開鍵（`-----BEGIN PUBLIC KEY-----` から最後まで）を貼って保存
4. 出てきた **Key ID** を控える

### 2. Cloudflare に入れる

Cloudflare → Workers & Pages → `travory-web` → **Settings → Variables and Secrets**（Production）に：

| 名前 | 値 | 種類 |
| --- | --- | --- |
| `CLOUDKIT_CONTAINER_ID` | `iCloud.com.gmail.taismryotasis.Travory` | Text |
| `CLOUDKIT_KEY_ID` | 1 で控えた Key ID | Text |
| `CLOUDKIT_PRIVATE_KEY` | `~/travory-web-cloudkit.pem` の中身をまるごと | **Secret** |
| `CLOUDKIT_ENVIRONMENT` | `production` | Text |

入れたら、もう一度デプロイする（GitHub に push するか、Deployments から Retry）。
Preview の環境に `CLOUDKIT_ENVIRONMENT=development` を入れておくと、Xcode から動かしたアプリ（Development）で試せる。

### 3. CloudKit のスキーマを Production へ反映する

`SharedTravelPlan` に `webViewEnabled`（INT64）と `webViewToken`（String）を足した。**反映しないと、Production でスイッチをオンにする保存が失敗する**（共有そのものは今までどおり動く）。

1. Xcode から動かしたアプリ（Development）で、共有した旅行の「ウェブでも見られるようにする」を一度オンにする（Development にこの2項目ができる）
2. CloudKit Console → Schema → Record Types → `SharedTravelPlan` に `webViewEnabled` と `webViewToken` があるのを確かめる
3. **Deploy Schema Changes…** で Production へ反映する

> 索引（Queryable）は要らない。ページはレコード名（`shared_<計画のID>`）で1件取り、合言葉はサーバーで比べる。

## 確かめ方

- サイトのテスト：`cd ~/Developer/travory-web && npm test`（見本のレコードは `functions/_lib/__fixtures__/sample-record.json`。アプリの型から書き出したもので、本物のデータではない）
- 手元で動かす：`npx wrangler pages dev dist`（鍵を入れていなければ「読み込めませんでした」になる）
- 本番：アプリでオンにして、リンクを iPhone と Android（か PC のブラウザ）で開く。オフにすると「見られません」になる

## テスト段階で見る（本番に出す前）

本番（`travory-web.pages.dev`）は iCloud の **Production** を読み、App Store の版のための場所。
Xcode から動かした版は iCloud の **Development** に書くので、本番のページでは見られない。
そこでテスト用のサイトを分ける。

| | サイト | 読む iCloud | 開くアプリ |
|---|---|---|---|
| 本番 | `https://travory-web.pages.dev`（`main` ブランチ） | Production | App Store / TestFlight の版 |
| テスト | `https://dev.travory-web.pages.dev`（`dev` ブランチ） | Development | Xcode から動かした版（`#if DEBUG`） |

- アプリは `SharedWebPage.baseURL` で切り替える（DEBUG のときテスト用）
- Cloudflare の Settings → Variables and Secrets で、**Preview** の側に `CLOUDKIT_ENVIRONMENT=development` と、鍵の3つを入れる
  （**CloudKit Console の鍵の登録は Development と Production で別々**。同じ公開鍵を両方で登録し、それぞれ出た Key ID を Preview / Production に入れる。
  Production で登録していないと `401 AUTHENTICATION_FAILED` になる。確かめ：travory-web で `node scripts/check-cloudkit.ts <Key ID> production`）
- travory-web の `dev` ブランチを push すると Preview として出る（本番には出ない）
- **見本のページ**：テスト用のサイトでは `/v/sample/sample` で見本の旅行（パリ旅行）が出る。鍵も iCloud も要らないので、見た目だけならすぐ確かめられる。本番では出ない
- 手元で見るなら：travory-web で `.dev.vars` に `CLOUDKIT_ENVIRONMENT=development` を書いて `npm run build && npx wrangler pages dev dist` → `http://localhost:8788/v/sample/sample`
