# 設計：アルバムの共有（3.8・無料）

共有した旅行に参加していても、思い出タブのアルバムの写真は端末の中にしか無く、同行者には見えなかった。
ご要望（「思い出タブの写真や旅行計画の表紙も共有出来るようにして欲しい」）から、旅行のアルバムの写真を同行者と見せ合えるようにする。
表紙（ヘッダー写真）は 2.9 から共有している（`docs/設計_ヘッダー写真の共有.md`）。

## ルール（`SharedAlbumPhotos`）

1. 自分の写真を載せるのは、アルバムの帯で「共有する」を押した人だけ。**今までに入れた写真を勝手に載せない**
2. 同行者が載せた写真は、押していなくても自分のアルバムに入る。旅行のアルバムが無ければ作る
3. 自分が載せた写真を消すと、みんなのアルバムからも消える。同行者の写真を消すと、自分のアルバムからだけ消える（もう入ってこない）
4. 「やめる」を押すと、自分が載せた写真をみんなのアルバムから消す（自分の手元には残る）
5. 旅行のアルバムごと消すと、自分の写真を共有から消し、もうアルバムを作り直さない
6. 持ち主が共有をやめる・旅行を消すと、載っている写真をすべて消す。参加者が抜けると、その人の写真だけ消す
7. 1つの旅行に載せられるのは 500 枚まで

## データの持ち方

- パブリックDB `SharedTripPhoto`（1枚1レコード、ID は `tripphoto_<キー>`）
  - `planId`（String・**QUERYABLE**）
  - `addedBy`（String・**QUERYABLE**。退会のときに自分の写真を引く）
  - `photoKey`（String）
  - `image`（Asset）：長辺 2048px・JPEG 0.8（1枚 300〜600KB）
- キーはアルバムのファイル名 `<アルバムの id>_<UUID>.jpg` の UUID。取り込んだ写真も自分のアルバムの id で同じキーにする
- 一覧は `image` を除いて取る（開くたびに全部の写真を降ろさない）。取り込むときだけ写真を降ろす
- 端末（UserDefaults、旅行ごと）：`SharedAlbumUpload_`（オン）・`SharedAlbumKnown_`（前回載っていた写真と載せた人）・
  `SharedAlbumDismissed_`（消した同行者の写真）・`SharedAlbumNoAutoCreate_`（アルバムごと消した）

## いつ突き合わせるか（`SharedAlbumSync`）

- 思い出タブを開いたとき（共有している旅行すべて）
- 旅行のアルバムを開いたとき・写真を足したとき

## 気をつけること

- 共有コードを知っている人は写真を見られる（旅行の中身と同じ）。オンにするときの確認に書いている
- 取り込んだ写真も、Pro なら iCloud に預かる（`PhotoSyncService`）

## CloudKit の設定

**Production に反映してからリリースすること。** 反映していないと、共有している旅行のある人が思い出タブを開くたびに失敗する
（アルバムの帯に「やり取りできませんでした」が出る。ほかの機能には影響しない）。

1. Development：Xcode から実機で、共有した旅行のアルバムで「共有する」を押す（`SharedTripPhoto` ができる）
2. CloudKit Console（Development）の Indexes で、`SharedTripPhoto` の `planId` と `addedBy` に **QUERYABLE** を足す
   （無いと一覧が取れず、帯に「もう一度」が出る。レコードタイプがまだ無いときは0枚として扱うので、1 で最初の写真は載る）
3. Security Roles で `SharedTripPhoto` の `_icloud` に **Read / Create / Write**（`SharedTravelPlan` と同じ）
4. Deploy Schema Changes で Production へ反映する

**2026年11月21日に Production へ反映済み**（`planId`・`addedBy` に QUERYABLE、`photoKey` は索引なし、権限は `SharedTravelPlan` と同じ）。
